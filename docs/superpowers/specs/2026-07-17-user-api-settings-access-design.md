# 普通用户开放「接口与生成」权限 — 设计规格

日期：2026-07-17  
状态：已批准  
范围：Ciallo Studio 前端权限门禁（`App.tsx` / `SettingsPage` / 生图页跳转）

## 背景

当前管理页整页仅站长（`role === "admin"`）可进。「接口与生成」（API Base URL、API Key、模型/默认生成参数）存在本机 `localStorage`，未配置则无法生图。普通用户因此被卡住。

## 目标

- **登录后的普通用户（`role=user`）** 可进入并读写 **「接口与生成」**，以便配置 Key 并生图。
- **站长** 保留完整管理能力（接口 + 用户池 + 媒体）。
- **游客** 不可进入配置页；点入口引导去大厅登录。

## 非目标

- 不改后端/角色模型（仍 `admin` | `user`）。
- 不把 API Key 改为服务端共享；继续本机 `localStorage`（`ciallo-studio.settings.v1`）。
- 不对普通用户开放用户池、媒体（CF Worker / Telegram）配置。
- 不新增独立「设置」路由或生图页内嵌完整配置表单。

## 权限矩阵

| 身份 | 顶栏按钮 | 可进设置/管理页 | 接口与生成 | 用户池 | 媒体配置 |
|------|----------|-----------------|------------|--------|----------|
| 游客 | 管理 🔒 | 否 → 大厅登录 | — | — | — |
| 普通用户 | **设置** | 是 | 读写 | 隐藏 | 隐藏 |
| 站长 | **管理** | 是 | 读写 | 读写 | 读写 |

## 方案

采用 **同页分级（方案 1）**：沿用现有 `tab === "settings"` 与 `SettingsPage`，按角色裁剪可见分区与文案。不拆独立设置页。

### 1. App 门禁与导航

文件：`src/App.tsx`

- `isLoggedIn = Boolean(community.user)`
- `isStationMaster = community.user?.role === "admin"`
- **进入条件**：`isLoggedIn`（不再要求站长）
- **踢出条件**：已在 settings 页且未登录 → 踢回大厅（站长降级为 user 仍可留在页内，仅看到接口分区）
- **顶栏文案**：
  - 未登录：`管理 🔒`，`title` 提示需先登录
  - 普通用户：`设置`，无锁
  - 站长：`管理`，无锁
- `openSettings()`：
  - loading 中可先切到 settings（现有行为保留）
  - 未登录 → 日志提示 + `setTab("hall")`
  - 已登录 → `setTab("settings")`

### 2. SettingsPage 裁剪

文件：`src/components/SettingsPage.tsx`

- 入参增加或沿用 `communityUser`；以 `isStationMaster = communityUser?.role === "admin"` 判断。
- **非站长**：
  - 不渲染分区 Tab（接口设置 / 用户池）
  - 不渲染 `UserPoolPanel`
  - 不渲染「图片存储（CF Worker → Telegram）」区块
  - 页头：标题「设置」，描述「接口与生成」；不出现「用户池 / 媒体」文案
  - 仅展示「接口与生成」表单（与现站长接口区块一致：Base URL、API Key、模型、宽高比、分辨率、并发、拉模型列表、保存等）
- **站长**：保持现有完整 UI（分区 Tab + 用户池 + 媒体 + 状态卡片）。

### 3. 生图页跳转

文件：`src/components/StudioPage.tsx`（及 `App` 传入的回调）

- 「去配置 / 打开设置」类入口：
  - 已登录 → `onOpenSettings()`（进入设置/管理页）
  - 未登录 → `onNeedLogin()`（大厅登录）
- 不在生图页内嵌完整接口表单。

### 4. 文案与无障碍

- 非站长进入页时无「校验站长权限…」文案；可保留「校验登录…」或沿用 loading 空态。
- 游客被拒时的说明改为「请先在大厅登录后再配置接口」，不再写「仅站长」。

## 数据与安全

- 设置存储位置不变：`localStorage` key `ciallo-studio.settings.v1`。
- 前端裁剪仅为 UX/门禁；真正敏感操作（用户池 ban/delete）仍依赖现有 admin API + 服务端/mock 校验。
- 普通用户本机配置的 Key 仅存在其浏览器，不上传到社区后端。

## 错误与边界

| 场景 | 行为 |
|------|------|
| 游客点「管理」 | 去大厅，提示登录 |
| 用户登录后进「设置」 | 仅接口与生成 |
| 用户在设置页退出 | 踢回大厅 |
| 站长退出或会话失效 | 同踢回大厅 |
| 站长被降为 user（理论上少见） | 仍可留在页内，仅接口分区；用户池/媒体隐藏 |
| 未配置 Key 时点生图 | 与现一致；引导去设置（已登录）或登录（未登录） |

## 测试要点（实现时）

- 游客：导航有锁，无法停留在 settings。
- 普通用户：导航为「设置」；页内仅接口表单；保存后能生图。
- 站长：导航为「管理」；接口 / 用户池 / 媒体均可用。
- 用户退出：从 settings 被踢回大厅。
- 构建通过（`npm run build`）。

## 成功标准

1. 普通用户登录后能配置 Base URL / API Key 并成功生图。  
2. 普通用户看不到用户池与媒体配置。  
3. 站长能力与现网一致。  
4. 游客无法进入配置页。
